## The Problem

Autonomous vehicles need high-frequency, high-accuracy environment sensing — ideally **100+ frames per second** for safe highway operation. At 100 mph, a 50ms processing delay means the car travels **2.2 metres blind**.

| Approach | RTT | Effective FPS | Problem |
|---|---|---|---|
| Onboard GPU (NVIDIA Orin) | — | ~30fps | $500–$2000/unit, power-hungry |
| 4G LTE offload | ~61ms | **16fps**  | Too slow — dangerous at highway speed |
| 5G offload | ~15ms | **67fps**  | Marginal, unreliable in handoff zones |
| **6G offload (this project)** | **~10ms** | **98fps**  | Safe margin — and robot needs no GPU |

## Architecture

```
[Rutgers Robot — Raspberry Pi]  ──6G V2X (1ms)──►  [MEC Edge Server — A100 GPU]
  CameraSimulator (640×480 JPEG)                      YOLOv8n inference (~4.5ms)
  BSM broadcasts @ 10Hz (SAE J2735)                   SPAT traffic-light timing
  IoU Tracker (CPU-only, no GPU)    ◄── detections ──  WebSocket response
```

1. **Real YOLOv8 detection** — actual neural-network inference, not mock data
2. **IoU multi-object tracking** — persistent object IDs + motion trails, zero GPU on robot
3. **Physics-accurate network model** — 4G/5G/6G latency, bandwidth, jitter, packet loss
4. **V2X protocol stack** — BSM (Basic Safety Messages), SPAT (signal phase & timing)
5. **Before/After analyzer** — side-by-side 1280×580 comparison video

## Network Model

| Parameter | 4G LTE | 5G NR | **6G Sub-THz** |
|---|---|---|---|
| One-way latency | 25ms | 4ms | **0.5ms** |
| Peak bandwidth | 100 Mbps | 1 Gbps | **100 Gbps** |
| Jitter (σ) | 5ms | 0.5ms | **0.05ms** |
| Packet loss | 0.1% | 0.01% | **0.001%** |

---

## V2X Protocol

| Message | Direction | Rate | Purpose |
|---|---|---|---|
| `BSM` | Robot → Infrastructure | 10 Hz | Position, speed, heading (SAE J2735) |
| `SPAT_REQUEST` | Robot → RSU | 1 Hz | Request traffic-light timing |
| `SPAT` | RSU → Robot | on-demand | Green/Yellow/Red + time remaining |
| `VISION` | Robot → Edge | 30 Hz | JPEG frame for YOLOv8 inference |
| `DETECTION` | Edge → Robot | 30 Hz | Bounding boxes + confidence scores |

## Why This Matters for Tesla Autopilot

Tesla's FSD chip runs ~72 TOPS of onboard inference. As sensor resolution scales (4D radar, lidar, 8MP cameras), onboard compute hits limits. 6G MEC edge offloading:

- **Removes the compute bottleneck** from the vehicle
- **Enables lighter, cheaper hardware** — a $35 Pi-class robot achieves L4-grade vision
- **Scales elastically** — edge GPU pools absorb peak inference load
- **Shared road intelligence** — one edge server sees all V2X participants simultaneously

This prototype proves the latency math: 6G makes edge offloading physically viable for autonomous driving.
